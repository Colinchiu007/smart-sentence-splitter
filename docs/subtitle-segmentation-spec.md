# 字幕分割规范 v1.0（双实现共享）

> 目的：统一 smart-sentence-splitter（Python）与 Multi-Publish story2video-engine（TypeScript）
> 两套字幕分割实现的行为，使**同一场景文本 → 同一字幕块序列**。
> 范围：仅字幕层（subtitles）分割规则；场景层（scenes）与句子层（sentences）不在本规范内。
> 方案 C：共享规范 + 双实现对齐 + 共享测试向量。

## 1. 输入与输出契约

### 输入
| 字段 | 类型 | 约束 |
|------|------|------|
| `text` | string | 场景文本；去首尾空白后必须非空；长度建议 ≤ 2000（超长由上游场景层保证） |
| `min_chars` | int | 默认 8；字幕块最小字符数（不含清理后标点） |
| `max_chars` | int | 默认 15；字幕块最大字符数（含标点） |
| `time_method` | enum | `proportional`（默认）/ `equal` |

### 输出
```
[
  { text: string, display_order: int, start_time: float, duration: float, parent_segment_id: int }
]
```
约束：
- 输出块数 ≥ 1（输入非空时）；无空块、无纯标点块；
- 所有块拼接后**去掉清理标点**应能还原原文主体（不丢内容，只丢清理的孤立标点/引号）；
- `display_order` 从 0 递增；`start_time ≥ 0`、`duration ≥ 0`；
- 块文本长度（清理后）≥ min_chars（除末块因短尾合并仍不足外）且 ≤ max_chars × 2（强制切分窗口）。

## 2. 算法流水线（7 步，顺序固定）

```
输入 text
  ↓ Step 1  分句边界保留（句子优先）
  ↓ Step 2  引号感知预分割（说话内容/叙述分离）
  ↓ Step 3  长度切分（标点优先 + 配对引号保护，min/max）
  ↓ Step 4  短块合并（前块 <min / 纯标点短块 / 短尾）
  ↓ Step 5  标点规范化（开头标点修正 → 末尾标点去除 → 跨块引号清理 → 再去除）
  ↓ Step 6  超长强制分割（> max_chars 强制切）
  ↓ Step 7  时间戳分配（proportional / equal）
输出 subtitles[]
```

### Step 1 — 分句边界保留（句子优先）
- 语义边界优先：字幕块**不得跨句**。
- 句界字符集（句界归属前块）：`。！？…` + 英文 `.!?`（省略号 `…` 视为句界）。
- **引号保护**：句界字符出现在**未闭合引号内**时不作为句界（避免破坏引号配对，如 `“……走了。”` 的句号在闭引号内）。
- 实现：先按句界把 `text` 切成句子片段，后续 Step 2-6 在**每个句子片段内**独立执行；空片段丢弃。
- 替代语义：与"先分句再分块"等价；禁止用"块内句号后切分"替代（顺序不同会改变结果）。

### Step 2 — 引号感知预分割
- 目的：引号内的说话内容与引号外叙述**分属不同字幕块**，避免语义粘连。
- 配对引号集合：`“ ”`、`‘ ’`、`「 」`、`『 』`、`《 》`、`（ ）`、`【 】`、`[ ]`、`" "`、`' '`（ASCII 与中文成对，不跨类型）。
- 规则：维护引号栈；**外层配对闭合时，若引号内内容长度 ≥ min_chars，则在闭引号后切分**；引号字符保留在其所在片段内（由 Step 5 清理）。
- 短引号内容（< min_chars）**不切分**，内容并入上下文（避免产生孤立引号块/说话人引导短块）；
- 未闭合引号（句尾裸开引号）不切分，交由后续步骤处理。

### Step 3 — 长度切分（标点优先 + 配对引号保护）
- 逐字符累积当前块；遇到**优先级标点**且当前块长度 ≥ min_chars 时切分（标点归属前块）；
- 当前块达到 max_chars 时：优先在**最近的优先级标点**后切；无标点则在最近空格切；两者皆无则在 max_chars 处硬切；
- **配对引号保护**：当前块内存在未配对的左引号时，禁止在配对完成前硬切（可借用下个字符窗口，最多等到 max_chars × 2）。
- 优先级标点集（统一）：
  `。 ！ ？ ； . ! ? ; ， , 、 空格( ) 换行(\n)`

### Step 4 — 短块合并
按序处理相邻块：
1. 前一块长度 < min_chars → 与当前块合并；
2. 当前块为**纯标点短块**（长度 ≤ 2 且全部字符 ∈ 标点集，含引号）→ 并入前块；
3. 当前块为**短尾**（长度 ≤ 3 且前块长度 ≥ min_chars）→ 并入前块；
4. 合并后块仍 < min_chars 且无前块可并 → 保留（首块例外）。

### Step 5 — 标点规范化（4 子步，顺序固定）
1. **开头标点修正**：块首为 `，、。！？；.!?;` → 移到前块末尾（首块开头标点删除）；
2. **跨块引号清理**：块内成对引号保留；未配对的孤立引号删除（**必须先于末尾标点去除**，否则 `rstrip` 会被孤立引号挡住，如 `……。”` 的句号在引号后无法去除）；
3. **末尾标点去除**：块尾去掉 `。！？；，、.!?;…`（此时孤立引号已清理）；
4. **再次去除**：删除引号后暴露的新开头/末尾标点，重复子步 1 与 3 一次；
- 过滤空块（清理后为空的块删除）。

### Step 6 — 超长强制分割（平衡切分）
- 遍历 Step 5 结果，`len(block) > max_chars` 的块：
  1. 优先在优先级标点处再切（从后往前找最近标点；**切分点必须在块内部**，块尾标点不作为锚点）；
  2. **平衡约束**：若按当前切分方案切出的**尾块长度 < min_chars**，则将切分点前移至 `len(block) - min_chars`（保证尾块 ≥ min_chars）——优先在 `[len(block)-min_chars, len(block))` 区间内从后往前找最近标点，找不到则在该位置字面平衡切；
  3. 无标点/锚点无效（含平衡区间外）则在 `len(block) - min_chars` 处平衡切；
- 目的：避免强制切分产生 `< min_chars` 的孤悬尾块（如 `…慢慢炖煮` 被切成 `…慢慢炖` + `煮`，`煮` 单字块不合理）；平衡后如 `再配上八角桂皮黄酒`（9）+ `等香料慢慢炖煮`（8）。
- Step 6 之后**再执行一次 Step 5 清理**：强制切分可能产生新的孤立引号（切断了引号对）或块尾标点，需二次规范化；
- 注意：Step 4 合并可能产生超长块，此步兜底；块上限 max_chars × 2 内不再二次强制。

### Step 7 — 时间戳分配
- 父场景时长 `parent_duration`（秒，来自场景层）。
- `proportional`（默认）：`duration_i = len(text_i) / Σlen(text) × parent_duration`；
- `equal`：`duration_i = parent_duration / n`；
- **连续性约束**：`start_time_0 = 0`；`start_time_i = start_time_{i-1} + duration_{i-1}`（使用**舍入后的 duration** 累加，保证区间严格连续、互不重叠，不因浮点舍入产生 0.01s 间隙/重叠）；duration 保留 2 位小数。

## 3. 数据校验（实现必须满足的断言）
- [ ] 输入 text 去首尾空白后非空，否则返回空列表；
- [ ] min_chars ∈ [1, max_chars]；max_chars ∈ [min_chars, 64]；非法配置回退默认 8/15；
- [ ] 输出无空块、无纯标点块（含孤立引号）、无 > max_chars×2 的块；
- [ ] 输出块按 display_order 连续；
- [ ] 全部块文本拼接后，去除 Step 5 清理标点后与原文在"非标点字符"上一致（不丢正文）；
- [ ] 同一输入 + 同一配置，两次运行结果一致（确定性，无随机）。

## 4. 双实现一致性要求
- 两个实现必须通过**同一份测试向量**（见 tests/vectors/subtitle_segmentation_vectors.json）；
- 向量断言：`expected_blocks`（仅文本序列，不含时间戳）必须逐字一致；
- 时间戳断言：`time_method=proportional` 下相对误差 < 0.01s（浮点舍入）；
- 任何规则变更必须同步更新向量并双实现重跑。

## 5. 边界与已知取舍
- **分句优先 vs 后处理句号切分**：规范固定"先分句"（Step 1）。8002 从 v0.14 起按本规范执行（不再用后处理块内句号切分）；Multi-Publish 本地维持先分句。两实现行为一致是本规范的验收标准。
- **末尾标点去除**会丢失句号/问号等语义标点，但这是"字幕显示规范"的既定取舍（避免孤立标点闪烁）；如需语义完整（如朗读/配音），消费方应使用句子层（sentences）而非字幕层。
- **引号短块**：Step 2 例外 + Step 4 合并共同避免产生孤立引号块；但"他说："（3 字）这类说话人引导块可能短于 min_chars——允许保留（Step 4 首块例外），消费方可自行合并。
- **英文**：优先级标点含 `.!?;`；空格切分有效；词间不硬切（标点优先，空格次之）。
- **省略号**：`…` 视为句界（Step 1），`……`（两个）同属句界字符集。
